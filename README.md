# meeting-transcriber

即時會議逐字稿工具。全本機運作，不上傳任何音訊。

- 即時逐字稿，支援中英夾雜
- 說話者辨識（A / B / C），可改成真名並跨會議記住
- 歷史會議瀏覽，事後仍可編輯文字與命名說話者
- 模型可即時切換，也可讓兩個模型並排轉寫同一句話

## 安裝

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
```

用 3.13。ML 套件（torch、mlx-whisper）在更新的 Python 上常常還沒有 arm64 wheel，
pip 會退回從原始碼編譯或直接失敗。`python3` 指到 3.14 以上的話改成
`python3.13 -m venv .venv`。

聲紋模型（ECAPA，約 80 MB）第一次錄音時自動下載。ASR 的權重要自己按 **⬇**
（見下一節），之後就完全離線。

## 使用

```bash
.venv/bin/python run.py          # 開 UI → http://127.0.0.1:8823
```

第一次按「開始錄音」時 macOS 會要求麥克風權限。

其他命令：

```bash
.venv/bin/python run.py models                     # 看有哪些模型可用
.venv/bin/python run.py file 錄音.m4a               # 轉寫單一音檔
.venv/bin/python run.py compare 錄音.m4a \
    --models mlx-turbo,mlx-large-v3                # 多模型並排比對
```

## 怎麼判斷哪個模型適合你

中英夾雜是這類工具最容易失手的地方，而且結果跟你的口音、講話速度、
英文詞的長度都有關，沒有通用答案。兩種做法：

- **邊用邊比**：模型可以**勾選多個**。標著「主要」的那個是逐字稿正文，
  其餘每一句都會再跑一次並排顯示在下面，附各自的延遲。
  按 ☆ 可以把任一個換成主要。
- **拿固定音檔比**：錄一段自己平常開會的講法，用 `run.py compare` 跑，
  同一段音訊對不同模型才是公平比較。

勾越多，每一句要跑的推論次數就越多（三個模型 = 三倍時間），
超過兩個畫面上會提醒你即時性可能跟不上。想仔細比對時可以先錄再回頭看。

同一個模型可能有兩種跑法，chip 上的小標籤是後端：`MLX` 走 Apple Silicon GPU，
`CPU` 走 ctranslate2（macOS 上沒有 Metal 後端，明顯較慢，留著是為了跨平台對照）。

`mlx-turbo` 是預設，在 Apple Silicon 上 RTF 約 0.08，即時很有餘裕。
覺得不夠準就往 `large-v3` 試，覺得太慢就往 `medium` / `small` 退。

chip 上有 **⬇** 代表還不能用，按了才會準備：缺 Python 套件的（SenseVoice、
Paraformer）會執行 `pip install`，裝進跑這支伺服器的那個 Python 環境（也就是
`.venv`）；套件有了但**權重還沒下載**的則開始抓權重（large-v3 約 2.9 GB、
turbo 約 1.5 GB、small 約 459 MB）。兩種都會即時顯示進度，完成後 ⬇ 消失、
可以勾選，不用重開。

勾選之後模型就**立刻載進記憶體**，不是等按下開始錄音才載。第一次載入要暖機，
放在錄音開始之後就會變成你在講話卻沒有逐字稿出來。

`進階` 區的**提示詞**對混說影響很大。原因是 whisper 的 decoder 本質上是一個
語言模型，一個字一個字續寫，同時參考聲音特徵和「已經寫出來的文字」。
提示詞的作用是假裝前面已經有一段文字，讓它模仿那個文體——包括**要不要混用兩種語言**。
所以提示詞不是在說「這段音檔講什麼」，而是在說「用什麼文體寫下來」。
寫成你平常講話的樣子，效果最好。

## 錄音模式（預設開啟）

`進階` 區有一個「錄音模式（不丟音訊）」的勾選框，預設是開的。

開啟時，每一句話的音訊會先寫成一個暫存檔，轉成文字後**立刻刪除那個檔**。
磁碟上永遠只有還沒轉完的部分。畫面上方會顯示「待解析 N 支音檔 · 容量」，
那個數字往上跑代表 ASR 落後了——但**內容不會遺失**，只是逐字稿晚出現。

關掉的話音訊完全不落地（隱私較好），代價是模型跟不上時會丟音訊。
丟音訊的後果不是「少一段」而是「**句子缺字**」——看起來正常但少了幾個字，
比空白更難發現。實測在同樣的過載下，關掉會掉超過一半的內容。

不管開或關，只要一句話進了轉寫佇列，逐字稿上就會先出現一列骨架，轉好之後
才換成文字——所以「有沒有收到我這句話」隨時看得出來。

按「停止」後如果還有積壓，狀態會變成「收尾中」並繼續把剩下的轉完，
全部轉完才算結束（開始錄音在這期間是鎖住的）。這時不要關掉程式。

## 說話者辨識怎麼用

1. 錄音時會自動分群，標成 `Speaker A`、`Speaker B`
2. 點一下說話者標籤，改成真名（例如 `Daniel`）
3. 那一群的聲紋就存進人物庫，**下一場會議同一個人第一句話就會被認出來**

分群在會議開頭最不準（群心還沒收斂），程式會每隔幾句自動全域重算並
**回頭修正前面標錯的段落**（畫面上會閃一下）。也可以手動按「重新分群」。

太短的語句不會被拿去開新的說話者——實測一句 1.6 秒的話，聲紋跟同一個人
其他每一段的相似度只有 0.14~0.31，比不同人之間還低。那種向量只會製造
一堆假的 Speaker，所以短句一律併進最像的那一群。

人物庫比對門檻刻意設得比分群門檻高：**把陌生人誤標成「Daniel」比留在
「Speaker A」糟糕得多**，所以寧可不認。

不留音檔。聲紋向量在會議進行時就跟逐字稿一起寫入資料庫，
所以事後改名還找得到聲紋。

## 收系統音訊（YouTube、Google Meet 對方的聲音）

麥克風收不到對方的聲音——那是從喇叭出去的。不需要安裝任何東西，用瀏覽器抓：

1. 先按「開始錄音」（分頁音訊是加到目前這場會議上的一條軌）
2. 按右上角「**＋ 分頁音訊**」
3. Chrome 跳出選擇視窗，切到「**Chrome 分頁**」，挑放 YouTube 或 Google Meet 的那個分頁
4. **一定要勾左下角「同時分享分頁音訊」**，不勾就只有畫面沒有聲音

這樣麥克風和分頁音訊會同時收，逐字稿上分成「現場」和「遠端」兩種——
遠端的段落左邊有一條藍線，說話者標成「遠端 A」。要停就再按一次那個按鈕，
或按 Chrome 自己的「停止分享」。

用本機喇叭放的話，程式不會把分頁的聲音再放一次（增益設 0），不會有回音。

**限制**：只抓得到 Chrome 分頁裡的聲音。桌面版 Zoom、Teams App 抓不到。

**不用 BlackHole 之類的虛擬音訊裝置**，因為那需要管理者權限。

## 換機器

「人物庫 → 全部匯出」會得到一個 JSON。到新機器匯入即可，不必重新收集聲紋。
單一人物也可以單獨匯出。

匯出檔記錄了建立聲紋所用的嵌入模型與版本。**換了嵌入模型，舊聲紋無法轉換**
（因為不留音檔，沒辦法重算），匯入時會直接擋下來而不是靜默混用。
